# 两条路径完整对比与选型

> 本技能同时提供两条技术路径。本文档说明它们的本质差异、各自能力边界，
> 以及**该选哪条**。选错会导致"做不到却以为能做到"，或"能做却绕远路"。

---

## 一、本质差异

| 维度 | 路径 A：浏览器后台 | 路径 B：官方 POP API |
|---|---|---|
| **操作对象** | 真实网页（`ktt.pinduoduo.com`）| HTTP 网关（`gw-api.pinduoduo.com`）|
| **执行者** | Agent 的浏览器（模拟人点击）| Python 进程（发请求）|
| **登录** | 用户微信扫码，会话在浏览器里 | OAuth 换 `access_token` |
| **资质要求** | 有快团团账号即可 | 企业资质 + 大团长 + **已对接小二** |
| **平台许可** | ⚠️ 灰色（自动化操作官方后台）| ✅ 正规（官方开放平台）|
| **稳定性** | 页面改版即失效 | 接口稳定，有版本管理 |
| **速度** | 慢（每次真实渲染）| 快（毫秒级）|
| **能否无人值守** | ❌ 需 Agent 在线 | ✅ 可定时/后台跑 |
| **实现载体** | 本 SKILL.md | `dudutt` Python 包（MCP server）|

---

## 二、能力矩阵（关键！）

这是**最重要的一张表** —— 它解释了为什么两条路都要保留：

| 动作 | 路径 A 浏览器 | 路径 B 官方 API |
|---|---|---|
| 查询团列表 | ✅ | ✅ `pdd.ktt.group.query.list` |
| 查询商品 | ✅ | ✅ `pdd.ktt.goods.query.list` |
| **发布商品** | ✅ 一键开团 | ✅ `pdd.ktt.group.create` |
| **改库存** | ✅ 修改团信息 | ✅ `pdd.ktt.goods.incr.quantity` |
| **下架商品** | ✅ **结束团 / 删除团** | ❌ **无接口**（只能库存归零）|
| **改价** | ✅ **修改团信息** | ❌ **无接口**（价格锁死）|
| 删除团 | ✅ 删除团 | ❌ 无 |
| 隐藏 / 置顶 / 标记 | ✅ | ❌ 无 |
| 订单管理 | ✅ | ✅ 有订单接口 |
| 售后处理 | ✅ | ✅ 有售后接口 |
| 物流发布 | ✅ | ✅ `pdd.ktt.order.logistic.create` |
| 批量操作 | ⚠️ 慢且易错 | ✅ 快，有幂等 |
| 定时任务 | ❌ | ✅ |

### 由此得出的核心结论

```
「下架」和「改价」→ 只有路径 A 能做
「批量」「定时」  → 只有路径 B 能做
```

**两条路是互补的，不是替代关系。**

## 三、为什么官方 API 没有下架和改价

不是没找到，是**确实不存在**。

官方 KTT 接口共 **36 个**（已逐条核对）：

- 商品/团购 9 个：`group.create` `group.query.list` `group.query.status`
  `group.upload.image` `goods.create.spec` `goods.incr.quantity`
  `goods.query.list` `goods.query.single` `goods.upload.image`
- 订单/售后/物流 11 个
- 供货商 16 个

其中**没有任何一个**能：
- 改变团的状态到「已删除」（`status=30`）—— 所以无法下架
- 修改已创建团购的价格 —— 所以无法改价

团状态码里有 `30:已删除`，但**没有 API 能触发这个状态**。
价格在 `group.create` 时确定，之后锁死。

**这是平台的产品设计，不是接口遗漏。**

## 四、选型决策树

```
用户提出需求
│
├─ 是「下架」或「改价」？
│   └─ 是 → 路径 A（官方 API 做不到，别再试了）
│
├─ 需要「批量」或「定时/无人值守」？
│   └─ 是 → 路径 B（若用户有资质）
│         └─ 无资质 → 拆分：路径 B 尽力，剩余动作留路径 A
│
├─ 只是查询/看数据？
│   └─ 路径 B 更快；无资质则路径 A
│
└─ 发布商品 / 改库存？
    ├─ 有资质 → 路径 B（更稳定）
    └─ 无资质 → 路径 A
```

## 五、路径 B 的前置条件（务必先确认）

**这是最容易卡住的地方** —— 很多人以为注册就能用，其实门槛很高。

在 <https://open.pinduoduo.com> 入驻时的实测结果：

| 选择的角色 | 可选主体资质 |
|---|---|
| （未选）| 企业开发者 / **个人开发者** / 商家 |
| 电商软件服务商 | **仅** 企业开发者 |
| **快团团团长** | **仅** 企业开发者 |

且「快团团团长」的官方原文说明：

> **仅开放给具备软件开发能力的快团团大团长作为系统对接使用，**
> **当前要求团长必须已对接快团团小二。**

拆解为 4 个条件：

1. ✅ 企业主体（营业执照）
2. ✅ 具备软件开发能力
3. ⚠️ 是快团团**大**团长
4. 🔴 **必须已对接快团团小二** ← 邀约制，最硬的坎

### 如何判断用户能不能走 B

```
问用户三个问题：
1. 有企业营业执照吗？
2. 有没有快团团小二/招商的联系方式？
3. 店铺规模如何（月流水量级）？

1 或 2 为「否」→ 建议走 A，不要浪费时间去申请
```

**不要给用户不切实际的期待** —— 个人团长基本拿不到路径 B 的资质。

## 六、安全与合规提醒

### 路径 A 的风险（必须让用户知情）

| 风险 | 说明 |
|---|---|
| **平台规则** | 自动化操作后台可能被判定违规，理论上存在账号风险 |
| **建议定位** | **半自动**：用户在场确认，Agent 执行。不做无人值守 |
| **页面改版** | 后台更新后选择器可能失效，需要重新侦察 |
| **不碰内部接口** | 伪造请求调 `/api/ktt_group/...` 属于逆向，明确禁止 |

### 路径 B 的优势

正规接入，有官方支持，无规则风险。**能走 B 就走 B。**

### 两条路的共同底线

- 不保存用户凭据（不存 cookie 文件、不要密码）
- 写操作必须确认（见 `safety-rules.md`）
- 失败如实报告，不伪装成功

## 七、路径 B 的安装与使用

```bash
pip install dudutt
```

配置：

```bash
export DUDUTT_CLIENT_ID="..."
export DUDUTT_CLIENT_SECRET="..."
export DUDUTT_ACCESS_TOKEN="..."
```

挂载到 MCP 客户端：

```jsonc
{
  "mcp": {
    "dudutt": {
      "type": "local",
      "command": ["python", "-u", "-m", "dudutt"],
      "environment": {
        "DUDUTT_CLIENT_ID": "{env:DUDUTT_CLIENT_ID}",
        "DUDUTT_CLIENT_SECRET": "{env:DUDUTT_CLIENT_SECRET}",
        "DUDUTT_ACCESS_TOKEN": "{env:DUDUTT_ACCESS_TOKEN}"
      }
    }
  }
}
```

### 后端选择

```bash
DUDUTT_BACKEND=api      # 官方 API（默认）
DUDUTT_BACKEND=browser  # 浏览器兜底（骨架，需校准选择器）
DUDUTT_BACKEND=mock     # 模拟，无需凭据，用于演示
DUDUTT_BACKEND=auto     # 按凭据可用性自动选择
```

### 先查能力再操作

```
调用 capabilities 工具 → 查看当前后端支持哪些动作
```

**这一步不能省** —— 否则会对着不支持的动作反复失败。

## 八、典型场景对照

### 场景 1：个人团长，要下架一个卖完的团

```
→ 路径 A
→ 团管理 → 结束团
→ 先确认（报出标题、说明不可逆）
```

### 场景 2：企业团长（有小二对接），要批量改 50 个 SKU 的库存

```
→ 路径 B
→ set_stock(goods_id, sku_id, quantity, idempotency_key=...)
→ 快、有幂等、不误伤
```

### 场景 3：企业团长，要改某个团的价格

```
→ 路径 A（即使有资质！因为官方 API 没有改价接口）
→ 团管理 → 修改团信息
```

### 场景 4：要每天早上自动检查哪些团快结束了

```
→ 路径 B（定时任务）
→ list_groups + 本地脚本 + 系统计划任务
```

### 场景 5：无资质的团长，想发新品

```
→ 路径 A
→ 一键开团
```

## 九、一句话总结

| 需求 | 选 |
|---|---|
| **下架、改价** | **A**（B 做不到）|
| 批量、定时、无人值守 | **B**（A 做不到）|
| 有企业资质 + 对接小二 | 优先 **B**，下架改价仍用 A |
| 个人团长 | 只能 **A** |
