# dudutt —— 快团团网店管理技能

> **先读这一句**：快团团的**官方 API 没有「下架」和「改价」接口**。
> 浏览器后台**有**。这就是本技能存在的理由。

---

## 一、两条路径，按条件选

| 路径 | 何时用 | 能力 | 状态 |
|---|---|---|---|
| **A. 浏览器后台** | 默认。用户有快团团账号即可 | 发布、**下架/结束团**、**改价**、改库存、查数据 | ✅ 今天可用 |
| **B. 官方 POP API** | 用户有**企业资质**且已对接快团团小二 | 发布商品、改库存、查数据；**下架只能库存归零、改价做不到** | ✅ 代码已就绪 |

**选择逻辑**：

```
用户要「下架」或「改价」
  ├─ 有资质 → 官方 API 做不到这两件事 → 仍需走 A
  └─ 无资质 → 只能走 A
用户要「批量/定时/无人值守」
  └─ 必须走 B（A 需要 Agent 在线）
```

**详细对照见** `references/mcp-vs-skill.md`。

## 二、铁律（违反会出真实事故）

### 🔴 三条绝对禁止

1. **绝不擅自对在售商品做写操作**。
   你的每一个动作都对应真实生意。**点「结束团」就是真的停售**，
   **改价就是真的改收入**，没有撤销按钮。

2. **写操作前必须逐项向用户确认**，并明确说出：
   - 要操作**哪个团 / 哪个商品**（报出标题，不要只说 ID）
   - **改前**的值和**改后**的值
   - 该操作**不可撤销**的后果
   用户明确同意后才执行。

3. **绝不用「测试」为借口动在售数据**。
   要验证流程，让用户自己决定是否新建测试团。
   **不要主动去点真实商品的任何管理按钮。**

### 🟡 三条操作纪律

4. **登录态由用户负责**。不要尝试自动登录、不要索要账号密码、
   不要存储 cookie。用户没登录就先请用户登录。

5. **只读优先**。能只读获取的信息，不要用写操作去试探。

6. **改完必须回报**。写操作后回报实际结果（截图或文字），
   并提醒用户到后台复核。

### ⛔ 一条技术红线

7. **严禁伪造请求调用后台内部接口**。
   后台自身的 `/api/ktt_group/...`、`/api/ktt_gateway/...` 属于**内部私有接口**，
   不是官方开放 API。直接调用属于逆向行为，明确违反平台协议，
   是风控重点打击对象，可能导致**账号封禁**。

   **本技能只通过真实浏览器点击操作页面。** 这是不可逾越的红线。

## 三、路径 A：浏览器后台操作流程

### 3.1 入口与登录

```
后台地址：https://ktt.pinduoduo.com/
登录方式：微信扫码（PC 端登录按钮 → 弹出二维码 → 用户微信扫码）
```

**登录检查**：打开后台若跳转到 `/login`，说明未登录 → 请用户扫码。
登录后应看到左侧菜单 + 顶部用户昵称。

### 3.2 后台功能全景（19 个模块）

登录后左侧共 **19 个一级入口** —— 先知道"有什么"，再决定"去哪做"：

| 模块 | 路由 | 能做什么 |
|---|---|---|

| 商品库 | `/goods_list` | 商品库管理 |
| 订单管理 | `/orders/order_list` 等 5 项 | 团购/店铺/积分/本地生活订单、团单管理 |
| 违规信息 | `/violation/list` | 违规记录 |
| 售后管理 | `/orders/batch_refund` 等 | 批量退款、待处理售后 |
| 商品核销 | `/orders/verification` | 券码核销 |

> **完整路由表、`data-testid` 清单、各模块子项见** `references/backend-map.md`

### 3.3 团购列表（首页，最核心）

```
URL: https://ktt.pinduoduo.com/groups?page=1&status=-1&type=0&category=-1
```

页面结构（已实测）：

- **筛选区**：团购类型 / 发布时间 / 结束时间 / 分类 / 搜索框 / 商品ID
- **操作按钮**：`查询` `重置` `一键开团` `批量移动分类` `批量编辑` `回收站`
- **团购卡片**：显示团购标题、价格区间、佣金、创建日期、实际收入、已跟团数、已浏览数
- **每张卡片底部**：`团数据详情` `手机查看` `订单管理` `团管理`
- **团状态**：`跟团中` / `已结束` 等

> 💡 **回收站**在列表页顶部 —— 误删的团可能从这里找回（应急用）

### 3.4 核心操作：团管理菜单

点击任意团购卡片下的 **`团管理`**，弹出菜单，包含：

| 菜单项 | 用途 | 风险 |
|---|---|---|
| 关联供货商 | 关联供货商 | 低 |
| 帮卖团长管理 | 管理帮卖 | 中 |
| **修改团信息** | **改价 / 改标题 / 改库存** | 🟡 中 |
| **结束团** | **下架（停止售卖）** | 🔴 **高，不可逆** |
| 复制团 | 以该团为模板新建 | 低 |
| **删除团** | **彻底删除** | 🔴 **最高，不可逆** |
| 隐藏团 | 从列表隐藏 | 低 |
| 标记团 | 打标记 | 低 |
| 置顶 | 列表置顶 | 低 |
| 查看操作记录 | 查看历史操作 | 低 |

**关闭菜单**：按 `Escape` 或点击页面空白处。

### 3.5 用 `data-testid` 定位元素（关键技巧）

快团团后台是拼多多的 **Beast 设计系统**，元素带 **`data-testid`** ——
**这类标识专供自动化，不随样式改版失效，优先使用**。

```python
# 推荐：稳定标识
page.locator('[data-testid="beast-core-button"]', has_text="查询")

# 次选：文字锚定
page.get_by_text("团管理", exact=True).first

# ❌ 禁止：hash 类名（每次发版都会变）
page.locator('.BTN_gray_15w5x36')
```

**已实测的 testid 清单见** `references/backend-map.md`。

### 3.6 弹窗陷阱（必读）

后台会**反复弹出**遮挡层，导致点击失效：

| 弹窗 | 处理 |
|---|---|
| 智能助手抽屉（"上午好，XXX"）| 点右上角关闭图标，或按 `Escape` |
| 置顶提示（"管理置顶团购"）| 点 `取消` 或 `知道了` |
| "打开消息页面，才可保证消息正常分流" | 点其关闭图标 |

**标准做法**：每次操作前先执行"关闭所有可见弹窗"，
再执行目标动作。否则会莫名其妙点不中。

## 四、路径 B：官方 POP API

### 4.1 前提（缺一不可）

1. **企业主体资质** —— 个人开发者不能选「快团团团长」角色
2. **是快团团大团长**
3. **必须已对接快团团小二** ← 这是邀约制，最硬的坎
4. 在 <https://open.pinduoduo.com> 完成入驻 → 创建应用 → 申请权限包
5. OAuth 授权换取 `access_token`

### 4.2 安装与配置

```bash
pip install dudutt          # 官方 API 路径
export DUDUTT_CLIENT_ID="..."
export DUDUTT_CLIENT_SECRET="..."
export DUDUTT_ACCESS_TOKEN="..."
```

### 4.3 MCP 工具（11 个）

| 工具 | 作用 |
|---|---|
| `capabilities` | **先调这个**，查当前后端支持哪些动作 |
| `health_check` | 检查凭据/连通性 |
| `list_groups` / `list_goods` / `get_goods` | 只读查询 |
| `publish_goods` | 发布商品（创建团购）|
| `set_stock` | 改库存 |
| `delist_goods` | 下架（api 后端实为**库存归零**变通）|
| `update_price` | 改价（api 后端**返回 unsupported**）|
| `list_official_apis` | 查 36 个官方接口 |
| `audit_log` | 查看写操作审计 |

### 4.4 能力边界（诚实版）

```
pdd.ktt.group.create        创建团购（=发布商品）  ✅
pdd.ktt.goods.incr.quantity 改库存                ✅
———————————————————————————————————————————————
下架     ❌ 官方无此接口 → 变通：库存全量置 0（≈售罄）
改价     ❌ 官方无此接口 → 团创建后价格锁死
```

**36 个官方 KTT 接口中确实没有下架与改价接口** —— 这是平台限制。
不要试图"再找找"，也不要向用户暗示"API 也能下架"。

### 4.5 写操作默认 dry_run

```python
publish_goods(title=..., goods_list=[...])              # 默认 dry_run=True，只预演
publish_goods(title=..., goods_list=[...], dry_run=False)  # 确认后才真执行
```

## 七、已知限制与风险

### 路径 A（浏览器）

- ⚠️ **平台规则风险**：自动化操作后台可能被视为违规。
  **建议半自动使用**（用户在场确认），不要无人值守长时间跑。
- ⚠️ **页面改版会失效**：优先用 `data-testid`，但仍需关注后台更新。
- ⚠️ **需 Agent 在线**：无法定时任务。
- ⚠️ **速度慢**：每次操作都要真实渲染。
- ⚠️ **部分路由动态**：供货商、直播工具、数据中心子项的路由是懒加载/动态的，
  需点击后观察实际地址。

### 路径 B（官方 API）

- ❌ **无下架接口**（变通为库存归零，效果不等价）
- ❌ **无改价接口**（团创建后锁死）
- ⚠️ 需企业资质 + 对接小二，个人拿不到

### 通用

- 两条路径**都需要用户自己的账号登录**，本技能不保存任何凭据。
- 写操作**没有撤销**。确认环节不是形式主义。
- 部分操作会**打开新标签页**（如打单工具），需检查 `context.pages()`。

## 九、出问题时

1. **点不中元素** → 先关所有弹窗（见 3.5），再用 `data-testid` 定位
2. **未登录/跳登录页** → 请用户微信扫码
3. **API 报 20004** → 签名错，核对 `client_secret` 与 MD5 大写
4. **API 报 20031** → 应用没申请该接口权限包
5. **API 报 20005** → IP 不在白名单
6. **API 报 10001** → 时间戳偏差超 10 分钟（校时）
7. **改价/下架被拒** → 这是**预期行为**，官方 API 本就不支持，改用路径 A
